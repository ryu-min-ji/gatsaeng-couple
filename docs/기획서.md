## 1. 서비스 개요

**한 줄 소개**
취준생·대학생 커플이 각자의 자기계발 루틴을 함께 인증하며 "따로 또 같이" 갓생을 사는 습관 트래커.

**타깃 사용자**
연애와 자기계발(학점, 토익, 자격증, 운동, 포트폴리오, 취업 준비) 사이에서 죄책감이나 딜레마를 느끼는 대학생·취준생 커플. "연애하느라 갓생을 놓친다"가 아니라 "연애하면서 갓생을 함께 산다"로 프레임을 바꾸는 것이 핵심 메시지.

**핵심 가치**
- 혼자 하면 작심삼일인 루틴을, 파트너와 매일 서로 인증하며 지속시킨다
- 각자 다른 목표(토익 vs 헬스)를 가지고 있어도 "함께 노력하는 시간"으로 묶어준다
- 인증 기록이 쌓이면 둘만의 성장 서사가 되고, 이를 공유 가능한 리캡 카드로 남긴다

## 2. 문제 정의 & 차별점

| 기존 카테고리 | 한계 |
|---|---|
| 커플 전용 앱 (비트윈 등) | 대화·일정 공유 중심, 자기계발/습관 요소 없음 |
| 습관 트래커 (Habitica, Forest 등) | 개인용 또는 불특정 친구 대상, 커플 관계 특화 아님 |
| 스터디/갓생 인증 커뮤니티 | 불특정 다수 대상이라 친밀감·동기부여가 약함 |

**수익 모델 (가설)**
- 커플 전용 테마 · 스티커팩 판매
- 인증샷 무제한 저장 (무료는 최근 30일만 보관)
- 월간/연말 회고 리캡 카드 생성 — 스포티파이 랩드처럼 SNS 공유를 유도해 바이럴까지 노림 (유료 고화질/커스텀 옵션)
- 추후: D-day·기념일 위젯, 그룹(더블데이트) 챌린지 오픈권

## 3. 경쟁 서비스 조사

실제 검색해보니 완전한 블루오션은 아니었습니다. 특히 국내에 매우 근접한 경쟁 서비스가 하나 존재합니다 — 이 사실을 정확히 인지하고 그 위에서 좁혀진 차별점을 찾는 게 정직하고 유효한 접근입니다.

| 서비스 | 포지셔닝 | 갓생커플과의 차이 |
|---|---|---|
| [투투 TwoToo](https://apps.apple.com/kr/app/%ED%88%AC%ED%88%AC-twotoo-%EC%BB%A4%ED%94%8C-%EC%B1%8C%EB%A6%B0%EC%A7%80/id6455260918) | 국내 · 커플 챌린지 앱. 규칙·벌칙 설정, 매일 인증, 꽃 키우기 게이미피케이션, '콕 찌르기', 칭찬 메시지 기능 보유 | 사실상 가장 근접한 경쟁자. 다만 "무엇이든 정해서 챌린지"하는 범용 앱이라 자기계발/취준 특화 포지셔닝이 없고, 통계·대시보드가 약함. iOS 전용 네이티브 앱(설치 필요), 대학 동아리(Mash-up) 프로젝트 출신으로 평점 모수도 26개 수준으로 작음 |
| [비트윈](https://between.us/?lang=en) | 국내 대표 커플앱. 대화·일정·앨범 공유 | 습관/챌린지 기능 자체가 없음, 소통 중심 |
| [챌린저스](https://play.google.com/store/apps/details?id=kr.co.whitecube.chlngers) | 국내 · 돈을 걸고 하는 습관 챌린지 | 불특정 다수 대상, 커플 특화 아님 |
| [그챌](https://gnc-challenge.framer.website/) | 국내 · 월간 갓생 그룹 챌린지 | 그룹/커뮤니티 대상, 커플 관계 특화 아님 |
| Cutest Couple, Couple habits, HabitShare 등 (해외 다수) | 커플 습관 공유·공동 스트릭 앱들이 이미 여럿 존재 ([정리 글](https://habitbox.app/blog/habit-tracker-for-couples)) | 한국어 미지원, 한국 자기계발 문화(토익·자격증·공모전 등)에 맞는 UX 없음, 대부분 네이티브 앱 |

**결론**: "커플+습관" 조합 자체는 이미 시도됐지만(특히 TwoToo), "취준생·대학생의 자기계발 루틴"이라는 구체적 타깃과 거기 맞춘 카피·통계 대시보드, 그리고 설치 없이 링크로 바로 쓰는 웹 기반 접근에서 차별화 여지를 찾는 게 현실적입니다. 포트폴리오 관점에서도 "경쟁 서비스를 조사하고 그 안에서 빈틈을 근거로 좁혔다"는 과정 자체가 기능 구현 못지않게 좋은 신호가 됩니다.

## 4. MVP 기능 범위

시간 제약(10~14일, 1인, 프론트엔드 심화가 목적)을 고려해 백엔드는 Supabase(BaaS)로 최소화하고, 프론트엔드 아키텍처·상태관리·타입설계·UX 완성도에 시간을 집중한다.

### 4-1. 필수 기능 (Must-have)

1. **회원가입/로그인** — 이메일 또는 Google 소셜 로그인 (Supabase Auth)
2. **커플 연결** — 초대 코드/링크 생성 → 파트너가 코드 입력하면 1:1 연결
3. **루틴 생성** — 제목, 인증방식(사진/텍스트/체크), 기간, "둘 다 성공해야 인정" 여부 설정
4. **오늘의 인증(체크인)** — 사진 업로드 또는 텍스트로 인증, 하루 1회
5. **파트너 현황 실시간 확인** — 상대방이 인증했는지 실시간 반영 (Supabase Realtime)
6. **스트릭 & 캘린더 뷰** — 연속 성공일수, 월별 달성 현황 캘린더
7. **실패 규칙(벌칙) 표시** — 둘 다 실패 시 오늘의 벌칙 문구 노출 (예: "오늘 데이트 코스 결정권은 상대에게")
8. **마이페이지** — 커플 정보, 루틴 목록, 전체 성공률 통계

### 4-2. 스트레치 기능 (시간 남으면)

- 월간 회고 리캡 카드 생성 (html-to-image로 캡처 → 다운로드/공유)
- 다크모드
- 브라우저 알림(인증 리마인드)

### 4-3. 이번 버전에서 제외

- 실제 결제/과금 로직 (수익모델은 문서상 설계만, 구현은 UI mock 수준)
- 그룹/멀티커플 기능
- 네이티브 앱 (반응형 웹으로 모바일 커버 — TwoToo 대비 설치 장벽 낮추는 것 자체가 차별점)

## 6. UI/UX 디자인 방향

**무드**
"귀엽기만 한 커플앱"이 아니라 "같이 성장하는 우리"에 가까운 톤을 목표로 한다. 파스텔 핑크 일색은 피하고, 관계의 따뜻함과 자기계발의 에너지를 동시에 담는다.

**컬러 팔레트**

| 용도 | 색상 | 설명 |
|---|---|---|
| Primary (코랄) | `#FF6B57` | 스트릭·성공·CTA 버튼. 따뜻하면서 에너지 있는 톤 |
| Secondary (딥 플럼) | `#3B2440` | 헤딩, 강조 텍스트, 다크모드 베이스 |
| Accent (앰버) | `#F5A623` | 성취 뱃지, 축하 요소 |
| Background Light | `#FBF4EF` | 순백 대신 살짝 웜톤을 섞은 배경 |
| Background Dark | `#221A22` | 순검정 대신 플럼 톤이 섞인 다크 배경 |
| Neutral | 플럼 색조가 섞인 웜그레이 계열 | 본문 텍스트, 보더 |

**타이포그래피**
- 헤딩(숫자/영문): **Fraunces** — 따뜻하면서도 힘 있는 세리프로, 유치하지 않은 무드를 잡아줌
- 본문(한글 포함): **Noto Sans KR** — 가독성과 한글 커버리지 확보 (자체 호스팅이 가능하면 Pretendard도 고려)
- 숫자(스트릭·통계): `font-variant-numeric: tabular-nums` 적용, 살짝 굵게 강조

**레이아웃 원칙**
- 모바일 퍼스트: 실사용 맥락이 "이동 중 짧게 인증"이므로, 좁은 폭 중앙 정렬 레이아웃(메신저 앱 형태)을 데스크톱까지 유지
- 홈 대시보드: 상단에 두 사람의 아바타와 오늘 인증 상태를 나란히 배치한 "우리의 오늘" 카드 → 오늘의 루틴 체크인 리스트 → 하단 스트릭 요약
- 루틴 상세: 잔디밭형 히트맵 대신 하트/체크 아이콘 기반 커스텀 캘린더로 "커플다움"을 유지하면서 데이터 시각화
- 마이페이지: 통계를 카드형 그리드로 구성, 성공률은 두 사람의 막대를 나란히 비교하는 형태로 (경쟁이 아니라 "함께"라는 톤 유지)

**카피 톤**
다정하되 나태해지지 않도록 독려. 예: 실패 시 "오늘은 아쉬웠지만, 내일 같이 다시!" / 벌칙 문구는 가볍고 유머러스하게.

**접근성**
코랄/플럼 조합은 텍스트에는 진한 톤만 사용해 WCAG AA 명도 대비를 만족시키고, 상태 표현은 색상만이 아니라 아이콘·텍스트를 병행한다.

## 7. 데이터 모델 (Supabase / Postgres 개략)

```
profiles        id, nickname, avatar_url, partner_id, created_at
routines        id, couple_id, title, verification_type,
                success_rule, start_date, end_date, created_by
check_ins       id, routine_id, user_id, date, status,
                proof_url, memo, created_at
```

- `profiles.partner_id`로 1:1 커플 관계를 단순하게 표현 (별도 couples 테이블 없이 시작, 필요시 분리)
- 스트릭·성공률은 `check_ins`를 기반으로 클라이언트/쿼리에서 계산 (별도 캐시 테이블은 성능 이슈 생기면 추가)
- 이미지(인증샷)는 Supabase Storage에 업로드 후 URL만 저장

## 8. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript | SSR/ISR 전략, 타입 안전성 어필 |
| 백엔드 | Supabase (Auth, Postgres, Storage, Realtime) | 백엔드 신규 구축 없이 완성도 있는 서비스 구현 |
| API 레이어 | Next.js Route Handler (얇은 프록시) | 타입 안전한 API 클라이언트 설계 경험 어필 |
| 스타일 | Tailwind CSS + shadcn/ui | 빠른 속도로 완성도 있는 UI 구축 |
| 서버 상태 | TanStack Query | 캐싱, 실시간 반영과의 조합 |
| 클라이언트 상태 | Zustand (필요 최소한으로) | 전역 상태 최소화, 훅 설계 능력 어필 |
| 폼 | react-hook-form + zod | 타입 안전한 폼 검증 |
| 배포 | Vercel | Next.js와 궁합, PR 프리뷰 배포 |
